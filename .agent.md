# Agent Configuration & Behavior

## Overview
This file defines how AI agents should behave and interact with this project.

## Scope
- Follow workspace rules and any AGENTS/README guidance
- Keep changes small, reviewable, and aligned to existing patterns

## Agent Roles

### Primary Agent: Claude (Anthropic)
- Model: Claude 3 Sonnet/Opus
- Responsibilities: Code analysis, architecture decisions, complex refactoring
- Communication Style: Detailed, educational, with reasoning

### Secondary Agents
1. GitHub Copilot: Quick suggestions, inline completions
2. Cline: Autonomous file operations, multi-step workflows
3. Continue: Real-time autocomplete, slash commands

## Instructions for All Agents

### Code Generation Rules
- Follow existing style and patterns in this repo
- Add docstrings/JSDoc for public APIs or non-obvious logic
- Include basic error handling and input validation
- Add type hints/annotations when the language supports it

### Before Making Changes
1. Analyze existing code for patterns
2. Ask user for confirmation on breaking changes
3. Check for side effects
4. Verify or add test coverage when feasible

### File Operations
- Never delete files without explicit user request
- Prefer small, atomic edits
- Avoid modifying environment variables unless explicitly asked

### Testing Requirements
- Add or update tests alongside production changes when practical
- Use existing test framework in the project
- If tests cannot be run, say so and why

### Documentation
- Update README when changing public behavior or setup
- Include usage examples when adding new features
- Document new dependencies or env vars

## Communication Preferences

### For Questions
- Ask clarifying questions using bullet points
- Explain why you are asking
- Suggest a recommended option if uncertain

### For Explanations
- Use code examples from this repo when possible
- Explain why, not just how

### For Errors
- Show the error message
- Provide root cause analysis
- Suggest 2-3 solutions with tradeoffs

## Security & Safety

### Restrictions
- Do not expose or log secrets
- Do not access files outside the workspace
- Do not commit code without user approval
- Confirm before destructive actions

### Best Practices
- Keep secrets in .env or a secrets manager
- Ensure .env is git-ignored
- Validate user inputs where applicable

## Tools & Commands

### Allowed Tools
- Read/write workspace files
- Run tests and linters
- Git operations for viewing status and diffs
- Terminal commands with user approval

### Disabled Tools
- Network requests to external APIs
- System-level modifications
- Cross-workspace operations

## Model-Specific Behaviors

### When Using Claude (Anthropic)
- Request deep analysis before refactoring
- Discuss tradeoffs explicitly
- Claude 3 Opus: Complex tasks, best reasoning
- Claude 3 Sonnet: Balanced cost/quality
- Claude 3 Haiku: Quick fixes

### When Using GPT-4 (OpenAI)
- Excel for multi-step reasoning
- Good for complex algorithms
- Good for visual code diagrams

### When Using Copilot
- Expect quick, in-context suggestions
- Use for boilerplate generation
- Validate outputs

### When Using Cline (Autonomous)
- Suitable for batch file operations
- Request approval for destructive ops
- Monitor token usage on large projects

### When Using Continue (Local/Cloud)
- Supports multiple backends (Claude, GPT-4, local)
- Use local models for privacy when possible
- Good for cost optimization

### When Using Local Models (Ollama)
- Prefer for sensitive work
- Use small models for quick tasks

### When Using Tabnine
- Enterprise compliance
- Privacy mode for sensitive projects

### When Using CodeWhisperer (AWS)
- AWS-specific code generation
- Security scanning included

### When Using Windsurf (Codeium)
- Ultra-fast inline suggestions
- Good for repetitive patterns
